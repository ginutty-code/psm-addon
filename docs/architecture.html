Pet Stable Management — system map

From scraped HTML to a hunter's stable panel

Two repositories, one feed-forward pipeline. psm-data scrapes Wowhead and Petopia, cleans the result against nine hand-curated correction files, and compiles five .lua tables. psm-addon loads those tables into a WoW addon namespace and renders them as panels.

Solid lines trace real file dependencies read from psm-data/README.md and config.py (each step's declared input/output) — 07 → 08 → 09 is one continuous chain: 08 applies npcs_updates.csv to 07's raw scrape, and 09 reads that corrected list to pull coordinates and display IDs. Dashed violet lines mark where a Manual/ CSV is merged in; the dashed grey line off 04_extract_wowhead_families.py is different — the missing Whiptail family (id 315) is a constant hardcoded inside the script itself, not a Manual/ file. The dashed amber line is the only edge that crosses the repo boundary — python sync.py (config.sync_output_to_addon()) copying the five compiled tables into psm-addon/PetStableManagement_ModelsBrowser/Data/, where the .toc load order picks them back up. The Data/ subfolder keeps generated tables apart from that addon's hand-written Lua. As of A1, this is an explicit step rather than a side effect of running a generator: 06/12/13/14/15 only write to Output/, each stamping a PSM_DataSchemaVersion global from config.SCHEMA_VERSION; the addon's Schema.lua asserts that stamp on load and fails with one readable error on a mismatch, instead of nil-index errors scattered across every consumer.

The Models Browser is a second addon, not a folder. PetStableManagement_ModelsBrowser has its own .toc marked LoadOnDemand with RequiredDeps: PetStableManagement, so neither it nor its five generated tables are parsed at login; Loader:EnsureBrowser() pulls it in on first use — and Loader itself is never called by the browser, correctly: nothing loads its own loader. Being a separate addon is also why _G.PSM has to exist — two addons get two ns tables and cannot share one. Core is private: every core file takes the client's local _, ns = ... and attaches to that per-addon table, and nothing fans out from Core.lua to the rest of Addon Core the way earlier drafts of this diagram drew it — sharing a namespace isn't a dependency, so that's now just column grouping, not a line. What is a real, drawn edge: Core.lua feeds PublicAPI, styled the same dashed amber as sync.py on purpose — it's the addon-internal version of the same idea, a curated fifteen-name whitelist (Shared/PublicAPI.lua) published onto _G.PSM, loaded last so every module has attached first; reading an unpublished member raises rather than returning a silent nil. Core reaches the other way through ns.Browser, a proxy table that forwards both reads and writes to _G.PSM. Both directions are enforced by Tests/spec/boundary_spec.lua. The full breadth of that whitelist's consumption (every Models Browser file reads through it somewhere) is the soft band linking the two columns, not individual lines — only the handful of specific, notable call patterns get a precise edge, same restraint the original diagram used. PanelManager:CreateBasePanel/TogglePanel is used by Panel, TeamsPanel, ModelsPanel, SpecialTames, AbilityBrowser, and ModelsFilters. RowManager:CreateBaseRow is shared by Row, GridView, GroupedView, and ModelRow — its ReleaseModel is the one definition eight independent hand-written copies of "stop tracking this model" collapsed into. PopUpManager backs the magnifier/roulette popups in ModelRow, ModelsPanel, PetRoulette, OptionsPanel, SpecialTames, and NPCRow, and itself calls back into RowManager and PanelManager. State (Store/Filters/Selections) is newer infrastructure than the rest of this column: ModelsDataLoader and NPCDataLoader both memoize their expensive per-family computation through Store:Selector, invalidated by a version-counter bump rather than a manual cache-clear call.

NPCRow and its data-side pair NPCDataLoader are the text-table "NPC view" alternative to the 3D model grid — deliberately model-free, so NPCDataLoader reads _G.ModelsData directly (the same shortcut PetModels.lua takes) instead of joining through ModelsDataLoader, and NPCRow reads PSM.NotesData directly for its per-row note indicator.
